# 餐边柜 SKU Studio

一个为餐边柜产品准备的标准 SKU 清单生成器。前台支持「单柜 SKU」与「组合柜 SKU」两种流程，适配桌面、平板和手机；配套一个只在本机运行的可视化编辑器，用来维护所有可见文案、类目、外观、公告与前台源码。

- 纯静态前台：HTML + CSS + 原生 JavaScript，无第三方依赖。
- iOS 风格液态玻璃界面，包含柔和环境光、玻璃层、过渡动效与深浅色模式。
- 桌面端「模式 + 当前条件」合并为吸顶工作栏，长列表筛选时仍可随时切换模式、回看条件。
- 组合柜使用紧凑单行编辑器，多个组合也能快速纵向浏览；柜体按「系列 → 门型 → 宽度」级联展开选择。
- 组合配置右侧提供实时预览，并可在删除前打开大图查看。
- 顶部「产品画册」集中展示全部柜体线稿，支持分类、搜索、款式、宽度和颜色筛选。
- 全部前台文案由 `js/site-config.js` 驱动，不写死在页面里。
- 本地编辑器支持实时预览、类目维护、主题调整、公告发布和源码编辑。
- 一键启动：Node.js 本地服务负责代码同步与自动备份。
- 可直接构建并部署到 **Cloudflare Pages**。

## 快速开始

### 启动本地编辑器

环境要求：**Node.js 18.17 或更高版本**（推荐 20 / 22 LTS）。

Windows：

```text
双击「启动编辑器.cmd」
```

macOS / Linux：

```bash
bash start-editor.sh
```

如果脚本没有可执行权限，直接用 `bash` 运行即可；也可以使用 npm：

```bash
npm run editor
```

启动脚本会自动打开：

- 编辑器：`http://127.0.0.1:5173/editor.html`
- 完整前台：`http://127.0.0.1:5173/`

如果 5173 端口被占用，服务会自动顺延到下一个可用端口，请以终端输出的地址为准。按 `Ctrl + C` 或关闭命令窗口停止服务。

只想启动服务、不自动打开浏览器时：

```text
启动编辑器.cmd --no-open
# 或
bash start-editor.sh --no-open
```

> 编辑器依赖本地 Node 服务写文件，不能直接双击 `editor.html` 使用。只看前台时，部署到 Cloudflare Pages 后无需任何服务端。

### 构建静态部署包

```bash
npm run build
```

构建结果在 `dist/`，只包含前台需要的文件；编辑器、Node 服务端与本地工具不会进入线上站点。

### 项目自检

```bash
npm run check
```

检查 JavaScript 语法、站点配置、类目数据与静态资源引用。

## 可视化编辑器

本地编辑器分成五个模块：

### 页面文案

所有前台可见文字都在这里编辑：

- 页面标题、描述、语言；
- 品牌标识、顶部导航；
- 首页标题、副标题、指标；
- 单柜 / 组合柜两种流程的步骤名、标题与提示；
- 全选、清空、上一步、下一步、复制、重新开始；
- 选项描述、组合状态、结果页标签与格式；
- 颜色显示名、款式名称；
- 弹窗、公告栏、网站使用说明与页脚。

带 `{...}` 的字段是格式模板，编辑器会提示可用变量，例如 `{count}`、`{height}`、`{value}`。步骤的 `key` 与 `actionType` 属于内部结构，没有开放编辑。

### 类目数据

维护 `js/catalog.js`：

- 系列 / 门型名称；
- 站脚高度与落地高度（编辑器分两个输入框，保存时合并为 `1020/870` 这样的高度组）；
- 宽度、深度；
- 颜色多选；
- 「待补价」等备注；
- 新增、复制、删除系列、门型或尺寸。

门型默认收起，点门型左侧箭头展开尺寸；该门型的复制、删除和「添加一行尺寸」都在展开区底部。顶部「展开全部 / 收起全部」可整体控制。保存前会校验必填项、高度组格式、宽度/深度数值和颜色。删除系列/门型等破坏性操作会二次确认。

数据字段顺序固定为：

```js
[系列, 门型, 高度组, 宽度mm, 深度mm, 颜色, 备注]
```

### 外观主题

- 强调色与渐变辅助色；
- 极光 / 沙丘 / 花雾 / 石墨四种环境背景；
- 默认外观（跟随系统 / 浅色 / 深色）；
- 玻璃模糊、圆角与动效开关；
- 公告横幅、首页指标、页脚、访客主题切换的显示开关。

修改后点击顶部「保存并应用」即可反映到预览和前台。

### 公告中心

支持新建、编辑、上线、下线与删除公告，并可设置：

- 标题、正文、徽标、类型；
- 发布时间与失效时间；
- 置顶、是否允许访客关闭横幅；
- 附加链接和链接文字。

公告写入 `js/site-config.js`。本地发布后前台预览会立即刷新；**已经部署到 Cloudflare Pages 的线上站点，需要重新提交/部署后才会更新**。

### 源码编辑

直接编辑以下文件：

| 文件 | 用途 |
| --- | --- |
| `index.html` | 前台结构 |
| `css/tokens.css` | 设计变量、共用玻璃与基础样式 |
| `css/app.css` | 前台页面样式与响应式 |
| `js/app.js` | 前台筛选 / 组合 / 结果逻辑 |
| `js/site-config.js` | 全部站点文案、主题、公告 |
| `js/catalog.js` | 类目数据 |

保存时：

- 服务端会做 JavaScript 语法校验；
- `site-config.js` 与 `catalog.js` 还会额外校验数据结构；
- 每次写入前自动备份到 `.backups/`（最多保留 40 份，已被 Git 忽略）；
- 保存后自动刷新右侧预览。

需要恢复误删内容时，在 `.backups/` 中找到对应时间戳文件夹，将其中的文件复制回项目对应路径，再刷新前台即可：

```text
.backups/20261025-112848-xxxx/
├─ js/site-config.js
├─ js/catalog.js
└─ …
```

备份是纯本地文件，不会进入 Git，也不会发送到网络。

编辑器自身的文件没有列入可编辑清单，避免误改后无法进入编辑器。

### 快捷键与安全

- `Ctrl + S` / `⌘ + S`：保存当前编辑器内容或当前源码文件；
- 源码编辑器内 `Tab`：插入两个空格；
- 有未保存内容时离开或关闭页面会提示；
- 本地服务只监听 `127.0.0.1`，并校验 Host / Origin，不使用跨域访问；
- 编辑器没有账号系统，请只在本人电脑上运行，不要将 Node 服务暴露到公网。

├─ server/server.js            # 零依赖本地服务 + 文件同步 API

## 部署到 GitHub 与 Cloudflare Pages

### 一键提交（Windows）

目标仓库：<https://github.com/lyy197673/sku-SCQ>

直接双击项目根目录的 **`一键提交代码.bat`** 即可：

1. 首次运行会从 GitHub 获取仓库的 Git 历史；
2. 自动暂存所有改动并提交；
3. 推送到当前分支；
4. Cloudflare Pages 收到推送后自动重新构建。

首次运行如果弹出 GitHub 登录窗口，按提示完成授权即可。脚本只使用本机 Git 凭据，不会在项目里保存 Token。

### 1. 手动上传到 GitHub（备用）

在项目根目录打开终端：

```bash
git init
git add .
git commit -m "feat: 餐边柜 SKU Studio"
git branch -M main
git remote add origin https://github.com/<你的账号>/<仓库名>.git
git push -u origin main
```

> 不要提交 `.backups/`、`.artifacts/` 与 `dist/`，仓库中的 `.gitignore` 已经排除。公告和文案的线上更新依赖 `js/site-config.js`，所以要随代码一起提交。

### 2. 在 Cloudflare Pages 连接仓库

1. 登录 Cloudflare Dashboard，进入 **Workers & Pages → Create → Pages → Connect to Git**。
2. 选择刚才的 GitHub 仓库。
3. 构建配置：
   - Framework preset：**None**
   - Build command：`npm run build`
   - Build output directory：`dist`
   - Root directory：留空（仓库根目录）
4. 环境变量可选：`NODE_VERSION=20`
5. 保存并部署。

每次推送到生产分支，Cloudflare Pages 会自动执行 `npm run build` 并发布 `dist/`。

### 3. 直接上传（不使用 Git）

```bash
npm run build
```

然后在 Cloudflare Pages 中选择 **Upload assets / Direct Upload**，上传 `dist/` 目录内的内容即可。以后更新时重新构建并覆盖上传。

### 发布公告或修改内容后的上线流程

1. 本地双击「启动编辑器.cmd」；
2. 在编辑器中修改并保存；
3. 推送代码：双击「一键提交代码.bat」，或手动执行：

```bash
git add js/site-config.js js/catalog.js
git commit -m "content: 更新公告"
git push
```

4. Cloudflare Pages 自动重新部署。若使用直接上传，则重新执行 `npm run build` 并上传 `dist/`。

线上站点是纯静态的，因此浏览器端没有写文件能力；所有内容维护都在本地编辑器完成后随部署上线，这是刻意的安全设计。

## 自定义提示

- 所有前台静态文案应优先在「页面文案」中修改，直接改 `js/app.js` 里的字符串会导致下一次可视化保存时难以维护。
- 颜色代码在类目数据中存的是字符（如 `黑白绿`），显示名称在「页面文案 → 颜色名称」中维护。
- 高度组的层数规则仍由 `js/app.js` 中的 `layersOf` 管理：
  - 首段高度为 1320：4 / 5 层；
  - 其他高度组：3 / 4 / 5 层。
  如需改变业务规则，可在源码编辑器中调整。
- 站脚 / 落地款由高度组的两段顺序判断；单高度组默认按高度阈值判断，显示名称在「款式名称」中维护。
- 修改 `index.html`、`app.js` 或样式属于高级操作；建议先用 Git 提交一次再编辑。

## 常见问题

**启动脚本提示找不到 Node.js？**  
安装 Node.js LTS 后重新打开脚本。Windows 可在终端执行 `node -v` 验证。

**端口被占用？**  
服务会自动尝试 5174、5175……请查看终端输出的实际地址。

**编辑器页面显示“需要本地服务”？**  
不要直接打开 `editor.html`，请通过启动脚本或 `node server/server.js --open` 访问。

**保存时报类目错误？**  
按提示检查高度组格式、宽度/深度是否为正数、是否至少选择一种颜色。错误字段会标红。

**线上修改后没有马上生效？**  
本地编辑器修改的是项目文件；需要提交并重新部署，线上地址才会变化。
